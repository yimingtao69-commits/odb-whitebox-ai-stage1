# ODB 系统说明书：一座有规章的智能工厂

适合：希望先用直观比喻了解系统，再逐步进入正式概念的读者。

## 1. 先说结论

ODB（可审计的分层智能生产系统）把用户输入、规范化文本、机器处理、运输、状态保存和审计回执放进同一套生产流程。它不要求读者相信某个模型“想得对”，而是要求每一步都有明确的材料、责任人、状态和回执。

ODB 的核心不是一句更漂亮的回答，而是四件事同时成立：

1. 任务知道自己正在做哪一步；
2. 货物只能沿登记好的树形道路运输；
3. 失败停在能恢复的断点，不抹掉已经完成的步骤；
4. 系统能留下足够证据，让人复核发生过什么。

## 2. 核心工厂是什么

核心工厂是一套处理**规范化文本和结构化符号**的受约束计算能力。它接收的不是照片、声音或随意聊天，而是已经经过入口适配、格式整理和边界检查的材料。

例如，用户写下“他打她”，系统可以把它表示为“动作=打、发起者=他、承受者=她”。如果再加入时间，表示中就增加时间字段。核心工厂关心的是字段、关系、条件和状态是否匹配，并不擅自判断现实中的“打”究竟属于哪一种事件。

当输入缺字段、语法不完整或两个材料互相冲突时，系统应返回“需要补充”“无法解析”或“存在冲突”等状态。它不会为了让句子看起来完整而替用户猜一个答案。

核心工厂的具体变量生成规则、推理机实现和模型调用策略属于内部保密内容。对外只承诺可验证的输入输出边界，不承诺“永不出错”或“永不产生幻觉”。

## 3. ODB 外壳做什么

核心工厂太干净，不能直接接触操作系统、文件、用户按钮和不稳定的外部服务。ODB 外壳负责把这些差异变成核心能处理的正式对象，再把结果交还给用户。

### 3.1 入口适配

环境适配层处理操作系统、编码和文件格式等外部差异。文件解析和内容清洗属于不同的入口职责：前者确认运行依赖，后者把内容转换成统一表示，两者必须绑定验收，不能互相冒充。

### 3.2 前台交互

用户从 Open WebUI 的客户可见界面进入。前台小妹负责收集对话、附件和确认，生成一张标准前端工单；菜单编号只是工单类型字段，不是直接通往后端部门的线路。前台总控把这张工单交给唯一的后端总控，再由后端安排正式工序。

### 3.3 五部制度

每个层、模块和车间都拥有同一组职责边界：自检、审计、控制、账房和通信。它们不是五个互相抢工作的聊天机器人，而是五种互补的制度职能。详细法律说明见《对外宪法与五部法律说明》。

### 3.4 运输与仓库

命令可以先到，货物也可以后到；但货物必须绑定一个已经登记的命令。没有对应命令的货物只能进入缓存或长期仓库，不能拆封。道路不通时，通信部把货物留在相应仓库并保存状态；发现异常的货物进入冻结仓库，由自检部决定上报和广播。

## 4. 树形道路如何工作

ODB 的生产通信是一棵树，不是一张可以任意拉线的网。命令沿“总控→层控制→模块控制→车间控制→功能组件”下行，回执按相反方向上行。跨部门联系必须先经过各自的直接上级和共同上级。

一个简单例子：A 下面有 A1、A2。A1 要把货物交给 A2，不能直接把货物塞给 A2；它要经过 A 的登记道路。若省级总控要调 A1、B1、B2，它必须先联系 A、B，再由 A 找 A1、由 B 找 B1 和 B2。能力可以自由组合，但层级路径不能省略。

## 5. 路条、车票和回执

- **工单**：后端总控规定要激活哪些能力，以及工序的先后和可并行关系。
- **路条**：起点账房根据已封存工单开具的端到端运输目标，描述货物最终应经过哪里。
- **车票**：当前节点账房开具的一段直接父子边运输凭证，只描述本段起点、终点和必要换乘点。动力载具只认已放行的车票，不认路条。
- **收条/回执**：证明某个节点已经收货、验货、处理或完成。邮政中枢收集本轮车票记录，交总账房核对，再由总审计留证。

运输必须使用动力载具；人工把货物从一个车间复制粘贴到另一个车间，不算自动化验收。

## 6. 一次任务怎样走完

1. 用户在前台提交问题和文件，并选择工单类型。
2. 前台总控生成标准工单，后端总控安排业务经停表。
3. 起点账房依据经停表和树形交通状态开路条、首张车票。
4. 自检部放行，通信部调用动力载具，货物到达下一站。
5. 接收站自检、盖过路章、开下一张车票；到达真正车间后才拆包并开工。
6. 车间完成个性化功能，统一封包，账房开下一段路条和车票。
7. 每个节点的收条顺树上行，最终由总账房汇总并交总审计。
8. 结果通过前台翻译成用户可读报告，缺资料、冲突或失败会明确标出。

## 7. 失败时会发生什么

失败不会被藏进一句“请重试”。系统保留原任务身份、货物身份、已完成车票和失败证据，把状态停在最近有效边界。恢复扫描从该边界继续，不重新放行、发车、拆包或重复调用已完成的功能。

如果自检发现违反现行宪法的操作，目标车间有权拒绝并冻结货物；高危货物走专用树形道路，完成本地冻结、向上报告和向下广播后，进入业务层中枢的隔离仓库。自检负责外来货物危险，移民管理负责内部本地模型工位和不受信任员工，两者不混为一谈。

## 8. 开发、运维和版本

功能扩张统一进入开发层；恢复既有能力是冷运维，重构已有能力是热运维。开发层与运维层同级，使用五部边界和树形通信，不拥有额外行政权力。运维优先于开发。

新版本拥有新身份，旧版本保留。新版本需经过预热、三次独立成功试用和用户接受；失败即丢弃新版本并回退旧版本。任何新增或迁移功能都先检查现有职责是否重叠：纯新增不得重复，权限迁移必须一减一加，纯删除可以只减不加。

## 9. 你应当记住的三句话

1. 核心工厂只处理已经规范化的文本和符号关系。
2. ODB 用树形道路、车票、仓库和回执把任务变成可恢复的生产流程。
3. 系统不把不确定性藏起来：缺资料就等待，有冲突就报错，失败就从断点继续。
