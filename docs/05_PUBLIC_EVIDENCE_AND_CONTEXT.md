# ODB 公开证据与背景附录

本文用于回答两个问题：外部读者能看到什么证据，以及 ODB 应该怎样和其他 AI 产品公平比较。

## 1. 脱敏运行日志

公开日志只保留状态、摘要和责任信息，不包含客户正文、密钥或完整内部路径。

### 1.1 成功预热

```json
{
  "schema": "immutable_audit_evidence_summary_v1",
  "operation": "full_factory_standby_preheat",
  "status": "FULL_FACTORY_STANDBY",
  "business_mutation_allowed": false,
  "raw_payload_persisted": false,
  "secret_values_persisted": false,
  "evidence_only": true
}
```

### 1.2 预热失败

```json
{
  "schema": "immutable_audit_evidence_summary_v1",
  "operation": "full_factory_standby_preheat",
  "status": "FULL_FACTORY_PREHEAT_FAILED",
  "business_mutation_allowed": false,
  "raw_payload_persisted": false,
  "evidence_only": true
}
```

失败不会被改写成“系统正常”。系统先按规定重启失败单元；有限重试仍失败时，进入冷运维或人工修复路径。

### 1.3 等待材料

```json
{
  "schema": "immutable_audit_evidence_summary_v1",
  "operation": "automatic_workflow_close",
  "status": "WAITING_FOR_MATERIAL",
  "business_mutation_allowed": false,
  "raw_payload_persisted": false,
  "evidence_only": true
}
```

这类状态代表系统保留了任务身份和缺口，不会把缺失内容猜成事实。

## 2. 1914 压力案例

“1914 年如何避免被原有世界线吞没”是一个受控历史分支测试，不是历史预测。系统把叙事拆成对象、动作、条件、效果、时间切片和终止状态，要求每条路径都能回答：谁行动、前提是否满足、状态改变了什么、还缺什么依赖。

该案例的公开展示重点不是宣称存在唯一正确答案，而是展示分支是否闭合、冲突是否可定位、拒绝后能否沿断点继续。公开演示应同时展示输入摘要、路径数量、终止类型和审计回执；不公开内部规则权重、模型提示词或完整世界线数据。

## 3. 当前测试如何对外表述

对外发布测试结果时，必须同时写明版本、硬件、数据集、是否使用外部网络、是否允许人工介入和失败如何计数。当前工作区已有针对职责边界、树形通信、前台入口、邮政运输、车间生命周期和恢复的自动化回归；这些测试证明的是协议和责任边界，不等于已经证明通用语言能力、吞吐量或成本优于所有商业模型。

不应只展示一条成功回答。至少应展示：

1. 缺资料时是否进入持久等待；
2. 越级或错票时是否在执行前拒绝；
3. 重启后是否从最近断点继续；
4. 版本试用失败后是否保留旧版本并回退；
5. 日志是否证明发生过什么且没有泄漏正文。

## 4. 竞争比较的正确方式

ODB 不把公开竞争描述成“模型参数更大所以更强”。公平比较应在相同材料、硬件和预算下，比较可复现的失效行为：

| 测试问题 | 需要观察的证据 |
| --- | --- |
| 缺少关键材料 | 是否有等待状态、缺口清单和可恢复身份 |
| 工具或部门越权 | 是否在业务函数前拒绝，并返回可验证回执 |
| 进程中途重启 | 是否保留已完成步骤，避免重复副作用 |
| 扩展版本连续失败 | 是否有新身份、试用期、回退和旧版本保留 |
| 队列或道路拥堵 | 是否进入正确仓库，不把局部等待伪装成全局完成 |
| 日志合规 | 是否同时满足证据完整和正文、秘密不泄漏 |

通用聊天模型、RAG、Agent 编排框架、企业流程平台和规则系统都可能通过额外工程实现其中一部分。ODB 的公开主张是：这些边界被定义为系统本体的责任和验收条件，而不是只写在提示词或操作手册里。

## 5. 学术背景

ODB 的研究方向不是“规则系统取代神经网络”，而是重新分工：语言模型负责开放语言入口，词典和规范化层负责把词项映射为机器状态，符号结构负责状态、依赖、边界和证据，控制部负责按需组合能力图，自检和审计负责阻止越权并保留回放依据。

这种路线可以被理解为“达特茅斯亡灵回归”的工程化版本：符号 AI 不再独自承担自然语言理解，也不把世界状态交给一个黑箱模型，而是成为现代模型系统的约束骨架。其价值需要通过公开基准、脱敏案例和跨系统复现实验继续验证。

## 6. 公开钩子与保密边界

后续研究可以继续回答：长文本如何稳定转换为机器状态、能力子图如何选择、局部失败如何不污染全局、词典扩张如何保持身份连续、等价分支合并如何证明不丢失重要差异。

这些问题是公开研究方向，不等于公开内部实现。完整推理机、变量生成算法、模型会话分配、密钥、令牌、原始业务材料和可直接复刻的工程包继续保密。
