# ODB 使用说明：把它当成一个会记账的办事大厅

适合：不需要知道程序内部结构，只想知道“我怎么用、它会怎么处理”的读者。

## 1. ODB 是什么

你可以把 ODB 想成一个办事大厅加快递中心。

- 你在前台提出问题、上传文件。
- 后台把事情拆成几个明确步骤。
- 每一步都有专门的工作人员处理。
- 文件不会凭空消失，路上也不会靠人工搬运。
- 哪一步成功、哪一步等待、哪一步失败，都会留下收据。

它不是只给你一段听起来很像答案的话。它要能说明材料是否齐全、哪些地方有冲突，以及出错后从哪里继续。

## 2. 你怎么使用

1. 打开客户界面。
2. 选择要办理的业务类型。
3. 在界面的“添加文件”位置上传材料。不要把文件内容直接假装成附件文字。
4. 写下问题或补充要求。
5. 提交一次，等待系统返回状态。

如果系统要求补材料，按提示补交；如果系统显示等待或失败，不要重复提交同一张新单。系统会沿原单身份自动恢复，除非它明确要求你开新单。

## 3. 它会不会乱猜

正常规则下不会用猜测填补关键缺口：

- 材料不全：告诉你缺什么，任务进入等待。
- 两份材料互相矛盾：告诉你哪两个地方对不上。
- 文件格式不支持：停在入口，并说明需要什么适配能力。
- 内部步骤出错：保留已完成部分，从出错处重试。

这不等于系统在所有现实问题上都正确。它只保证在已经声明的规则和输入格式范围内，优先给出可检查的状态，而不是把不确定内容说成确定事实。

## 4. 文件和货物怎么走

文件在系统里像包裹。后台给它贴上“这包要经过哪些窗口”的总路条，再给每一小段路开车票。

- 路条：总目标，说明要经过哪些部门。
- 车票：当前这一段路，说明从哪里到哪里。
- 收据：证明某一步确实收到或完成。

系统里的自动快递车只认车票。没有车票，通信部不会取货。没有对应业务命令的包裹不能拆开处理，只能暂存。

## 5. 为什么不能跨部门直送

ODB 像城市行政区。县里的窗口不能绕过市里直接接受省里的命令；跨区办事要先找各自的上级，再由上级转交。这样做是为了避免一个模块突然替另一个模块做决定。

这不会阻止组合能力。需要 A 区的窗口和 B 区的两个窗口时，后台可以同时调它们，但必须先联系 A、B，再由 A、B 各自联系下属窗口。

## 6. 出错和断电以后怎么办

系统会保存任务编号、包裹编号、已走完的车票和最后一张收据。重启后从最后一个确认点继续：

- 已经送到的不会再送一次；
- 已经拆开的不会再拆一次；
- 已经完成的功能不会重复执行；
- 没有完成的步骤才会重新尝试。

若发现包裹有危险或内部操作违反制度，系统会把包裹锁进冻结仓库，并留下报警记录。冻结不是普通等待，只有对应的自检和后续授权可以解除。

## 7. 五类工作人员，简单说

| 工作人员 | 主要工作 |
| --- | --- |
| 自检 | 检查能不能进、能不能出，发现危险就拦下并报警 |
| 审计 | 记录做过什么，保存证据，不替别人做决定 |
| 控制 | 安排步骤、先后和要叫哪些窗口 |
| 账房 | 记录编号、收据、车票、完成状态 |
| 通信 | 管路、红绿灯、仓库和自动运输车，不判断内容 |

还有开发层和运维层。开发层增加新能力，冷运维恢复旧能力，热运维重构已有能力。它们没有比业务部门更高的行政权力。

## 8. 你看到的结果是什么意思

- **已接收**：系统收到了你的工单或文件。
- **处理中**：某个车间正在执行步骤。
- **等待材料**：缺少继续所需的材料。
- **已拒收**：材料或身份不符合当前步骤。
- **已冻结**：自检发现高风险或制度违规，已隔离留证。
- **已完成**：所有必需步骤和两次命令核销都完成，回执链闭合。

## 9. 最重要的限制

ODB 目前公开承诺的是流程可靠性和证据可追溯性，不是现实世界判断的万能性。它不能替你读取没有适配器的照片或录音，也不能在规则本身没有定义时凭空创造事实。它会明确告诉你“需要补充”或“暂时无法处理”。
